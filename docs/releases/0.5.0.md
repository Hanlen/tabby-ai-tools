# v0.5.0 — Workflow aliases, Pi runtime and context compaction

Explicit workflow recordings now expose their recording, verification and archive status. Ask the assistant to save an alias such as `/pm1` after a completed `/remember` task; `workflow_status` and `workflow_set_alias` verify the intended recording and read back the saved alias. Checkpoint success is distinguished from archival. Rejected recordings show the reason, and failed archive writes can be retried from retained verified steps without replaying terminal commands. Follow-up goals wait for an in-progress archive. Ordinary tasks cannot be saved retroactively; retry buffers are session-local and do not survive restart.

## Runtime and recovery

- API connections can select an isolated **Pi SDK** runtime with pinned SDK 1.4.0 and an external **Node 22.19+** process. Host-advertised Tabby tools retain the existing terminal ownership, approvals, read-only rules and workflow checkpoints.
- `/compact` supports manual API/Pi context compaction with durable history and portable handoffs. Automatic compaction is opt-in. Pending input and interruption recovery notices remain pending until a normal Pi prompt imports them; truncated replies cannot complete a goal.
- High-frequency terminal output stays in the bounded local buffer and is read explicitly. Backend retry waiting shows elapsed time and a countdown only when supplied by the backend. Stop cancels the turn; recovery checks live results before confirming pending workflow steps. The plugin adds no model retry loop.

## Validation and limits

The npm tarball is inspected for runtime entry points, dependencies, bilingual documentation, artwork and bundled skill. Linux/macOS/Windows CI results and the verified tarball checksum are recorded in the GitHub Release.

Offline fixtures cover workflow alias follow-up, archive failure/retry, high-frequency output, backend waiting/cancellation and API/Pi context handling. The earlier isolated Linux Tabby fixture exercise is documented in `docs/pi.md`. No paid inference or original-task replay is performed for this release. Real provider/subscription access, SSH/PTY modification workflows and macOS/Windows desktop behavior remain outside this release's verification.
