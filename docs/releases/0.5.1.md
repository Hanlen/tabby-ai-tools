# v0.5.1 — Fix plugin installation without system Node

Version 0.5.0 added the optional Pi SDKs as ordinary runtime dependencies. Tabby therefore installed their full dependency tree even when Pi was unused. On systems without a `node` command on PATH, the `protobufjs` postinstall script could fail and block the entire plugin upgrade.

The pinned Pi SDKs are now build-only dependencies. A self-contained ESM bundle and third-party notices ship in `dist/pi`; the only ordinary runtime dependency is again `cross-spawn`. Installing or updating the plugin no longer installs the Pi/Google/protobuf dependency chain. External Node 22.19+ is still required when the optional Pi runtime is selected. Codex, Claude Code and the built-in API runtime retain their existing requirements.

Source installation copies the prebuilt runtime without invoking npm. Both READMEs, the guide, Pi/development documentation, bundled model guidance and the SVG/PNG overview explain the installation/runtime boundary. The robot GIF and reduced-motion image are preserved.

Local Linux / Node 22.19.0 validation passed the full offline suite (762 tests: 756 passed, 6 Windows-only skips), type checks, builds and bundle checks. Version 0.5.0 was reproduced failing at `protobufjs` postinstall with `node: not found`; 0.5.1 installs successfully under the same conditions. A new package check installs a real tarball with lifecycle scripts enabled, an explicitly available system shell and no `node` on PATH; a control postinstall must fail under the same conditions. It inspects the complete installed production dependency closure. Another regression copies only the Pi bundle outside the repository and completes local HTTP streaming and a host-tool round trip without installed SDK packages. All three operating systems run the package check in CI. GitHub Release records final results and the artifact checksum.

No paid model request or user task replay is performed. The package-manager checks and local HTTP fixtures do not establish a full Windows/macOS Tabby desktop upgrade or real provider access. Existing 0.5.0 recordings and conversations require no migration.
