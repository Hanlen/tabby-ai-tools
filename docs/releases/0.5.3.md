# v0.5.3 — Trusted GitHub Actions publishing

Formal GitHub Releases now trigger npm Trusted Publishing through GitHub OIDC. The workflow publishes the exact reviewed tarball attachment; no long-lived npm token, repeated browser publish authentication or second build is required after the one-time publisher binding. Existing account and package 2FA policies remain in place.

Publication requires the annotated release tag and successful Linux/macOS/Windows checks for both its branch commit and tag. It verifies the attached artifact checksum, release-note checksum, package identity and archive contents, rejects version overwrites or a backward latest tag, then waits for npm processing and compares the registry download byte for byte. Manual workflow dispatch defaults to validation only.

Both README illustrations and the SVG/PNG version label are current. The robot GIF and reduced-motion image are preserved. The bundled Pi SDK and default Electron utility runtime from 0.5.1 are retained, including installation without system Node and the optional compatibility Node path.

Local Linux / Node 22.19.0 validation passed the full offline suite (772 tests: 766 passed, 6 Windows-only skips), type checks, bundle checks, production builds and actual tarball installation with no node on PATH and lifecycle scripts enabled. New publishing-policy tests cover malformed tags, wrong commits, failed/missing platform checks, package identity, install hooks, traversal and private files. A real dry run checks the already-published 0.5.1 release without submitting it again. Final three-platform checks and the first real OIDC publication are recorded in the GitHub Release and publish workflow.

The v0.5.2 tag is retained without an npm publication after its macOS CI found a timing-dependent sudo lease test. The test now waits for observed refreshes and worker cleanup with bounded deadlines instead of assuming that a busy runner schedules the background process within 120 milliseconds. Runtime behavior is unchanged.
