# v1.0.0

## External MCP terminal connections

- Optional loopback MCP service, disabled by default, running through Tabby's built-in Electron runtime without requiring system Node.js.
- Named clients start read-only with no terminal access. Explicit grants enable snapshots, client-bound incremental cursors and bounded output waits, independently of the sidebar.
- Controlled input preview: `send_input`, `send_keys`, `attach_process` and `release_tab` use per-operation confirmation or explicit automatic permission, expiring client-bound leases and the shared terminal controller. No automatic interruption or replay; an unknown outcome requires reading the terminal before continuing.
- Portable `tabby-mcp` Agent Skill and credential-free service discovery assist pairing. Client configuration and authorization remain explicit. Credentials rotate and revoke independently; terminal scopes clear on restart/reconnect.

## Faster observation and private Codex login

- Default terminal snapshots wake on unread output or reliable shell completion, with 50 ms burst coalescing and a 200 ms continuous-output cap. Output alone does not prove completion or release multiline input ownership.
- Private Codex spaces offer official browser sign-in and local sign-out. Imported cache recovery requires newer credentials for the same user and workspace; explicit private sign-in/sign-out disables imports. History is retained and tasks are never resent.
- Fixed a browser-login race where a completion notification in the same stdout chunk as the start reply was lost.
- Fixed oversized MCP HTTP body handling so the adapter can flush HTTP 413 without its request iterator destroying the connection first. Unread bytes are drained and request timeouts remain bounded.
- Release artifact validation now requires the MCP runtime, notices and portable skill, alongside the existing Pi runtime checks.
- Stabilized authentication fixtures by using one token-expiration baseline across cache comparisons.
- Includes attachment highlight masking and conservative unknown-outcome handling for interrupted external MCP writes.

## Documentation and validation

Bilingual READMEs, setup/development guides, operation skills and synchronized overview SVG/PNG describe the 1.0.0 behavior. The overview is an illustration with example content; the robot animation and reduced-motion static fallback are retained. ChatGPT login and entitlement guidance was checked against the official authentication documentation.

Required local checks: skill bundle/check, TypeScript, the full regression suite, production build, diff checks, actual tarball inspection and installation with no `node` on PATH and lifecycle scripts enabled. Exact results are recorded in `VALIDATION.md`; the GitHub Release records branch/tag Linux/macOS/Windows CI and the verified tarball SHA-256.

Real Linux Tabby/Codex MCP reads and controlled command/release have earlier no-model acceptance evidence. This release review also verifies actual Linux Tabby/Electron MCP startup, HTTP body limits, a harmless real-terminal command/read/release and service shutdown. It adds no paid model calls or real account inference; other behavior uses subprocess, HTTP and host fixtures. Actual Cursor/Claude MCP clients, Windows/macOS desktops, old hosts, user SSH execution and Codex/Claude account end-to-end validation remain pending. Ordinary SSH shell command input remains blocked when idle process identity cannot be verified. Public/LAN access, OAuth server, external logs/workflows and automatic client configuration are outside the shipped scope.
