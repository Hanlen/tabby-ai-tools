# 0.8.0 — SSH attachments, native tab progress and connection/session configuration

Paste screenshots or add files in **Attachments**, choose a connected SSH terminal and upload into a unique private directory. Download remote regular files into the conversation's attachment cache. File bytes travel through the plugin, with streaming SHA-256 verification and native target-tab progress, rather than repeated model/base64 tool calls. The assistant can start, inspect and cancel the same operations through dedicated attachment tools.

Transfers reuse existing authentication. SFTP is preferred, followed by independent exec byte streams, exec base64 and a framed base64 protocol in a verified idle POSIX Shell. Capability failures permit fallback; policy failures and ambiguous results do not. Cancellation and receipts preserve the distinction between completed, failed and unknown writes. The ordinary terminal-reading/command-verification protocol remains unchanged.

This release also includes native Pi provider selection and the offline SDK 1.4.0 model catalog, four custom API protocols, explicit connection drafts, immutable custom-instruction snapshots and private Codex/Claude CLI history spaces. Existing connection identities and system-history compatibility remain available. Windows CLI discovery retains the 0.7.1 fixes.

Both READMEs, the guide, attachment/development/session documentation, model-facing skill and SVG/PNG overview describe the final capabilities. The overview is an illustration with example data; the robot animation and reduced-motion fallback remain available.

## Boundaries

- Upload receipts prove file integrity, not that a terminal Agent attached or read an image. Automatic attachment to an existing Codex composer and sidebar model image input are deferred.
- Paths belong to the outer SSH host/account. Nested SSH, containers, changed users and Agent sandboxes need explicit visibility checks. POSIX fallback tools must already exist; no runtime is installed remotely.
- The final PTY fallback requires reliable idle-Shell evidence and does not stop an existing Agent. An ambiguous PTY cancellation can leave a receiver waiting; inspect before releasing input or retrying.
- Local cached attachments retain metadata across restarts. Transfer receipts survive restarts; unfinished or other-window operations remain unknown and are never replayed automatically. Uploaded remote files remain until explicitly removed.
- Other native progress producers take precedence over this plugin's tab progress; transfer details remain available in the attachment panel.
- Real provider/account access, billing and full macOS/Windows desktop behavior are separate from offline/local-host tests. Routine verification makes no paid model calls. OAuth/cloud identity, advanced provider import/export and general read-screen cursor improvements remain deferred.
