# 0.7.1 — Windows Codex CLI discovery

Windows default configuration (blank or `codex`) now compares actual CLI versions across all PATH matches, desktop/standalone installs, user `.local/bin`, and known/npm global-prefix locations. A stale PATH entry no longer wins over a newer discovered CLI. Each new connection rescans without calling a model.

Version probes use semantic version ordering, a 1.5-second timeout, a 16-KiB output limit and at most four concurrent children. Synchronous process-launch errors are isolated to the failing candidate. Failed or unknown probes cannot outrank a known version; if every version is unknown, discovery order is retained and freshness cannot be guaranteed. CLI selection does not change account model entitlements.

An explicit `OpenAI\Codex\bin` directory compares only its child installations. Removed version-specific desktop entrypoints recover within the same installation. Existing explicit files and custom command names remain pinned. Linux/macOS lookup priority is unchanged.

English/Chinese READMEs, discovery/development guidance, bundled Tabby skill knowledge and the overview SVG/PNG now describe this behavior. The robot animation and reduced-motion fallback are preserved. The overview is an illustration with example tasks and connections, not a desktop screenshot.

Local validation uses Node 22.19.0. Release validation includes skill bundle/check, typecheck, full tests, production build, a real npm archive and installation with no node on PATH and lifecycle scripts enabled. Linux/macOS/Windows CI must pass before publication. Real account/model calls and an interactive Windows desktop session are outside this validation scope.
