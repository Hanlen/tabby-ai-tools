# v0.4.0 — Custom OpenAI-compatible providers and continuous agent goals

Add named **Custom (OpenAI compatible)** connections for user-supplied gateways and local services. Select **Chat Completions** (default) or **Responses**, enter a Base URL and model ID, and use a direct API key, an environment variable, or explicitly choose no authentication. No-key mode omits Authorization and does not read saved credentials. Model discovery uses `/models`, with manual model entry available when discovery is unsupported.

Custom connections share streaming text, continuous function-tool rounds, approvals, stop controls, goal tracking and persistent history. Protocol changes carry portable conversation context and goals into a new session without replaying tools; existing provider fingerprints remain compatible. Generic connections omit vendor-specific Thinking/cache parameters. Changing connection parameters cancels stale model discovery and connection-test results.

API and local Claude Code agents now continue active goals after ordinary text responses. Verified completion, a real blocker, an explicit pause, cancellation, token budgets, configured limits or repeated no-progress evidence ends continuation. Legacy 20-round defaults migrate to unlimited; explicitly configured limits remain available. The model picker follows model → reasoning effort for API and Claude Code, including provider defaults and manually entered models/effort values.

Add separate **Kimi API**, **Kimi Coding Plan** and **Alibaba Cloud Coding Plan** presets with China mainland/international regions, matching keys and models, native thinking parameters, usage handling and persistent Kimi session cache keys. Requests identify this client honestly. The release also includes the local Claude Code login integration added since v0.3.2, using the official CLI and an authenticated loopback MCP bridge; Claude API access remains separate.

Both READMEs, twelve language catalogs, configuration and development guides, provider architecture/roadmap notes, bundled model instructions and generated knowledge are synchronized. The editable SVG and exported PNG show v0.4.0 settings, custom providers, reasoning selection, terminal coordination and schedules, explicitly marked as an illustration. The robot GIF and reduced-motion static fallback are preserved.

Validation: skill bundle generation/consistency, TypeScript checking, 708 local tests (702 passed, 6 Windows-only skips), production build, Markdown rendering, image preview and `git diff --check`. The npm tarball is inspected before publication and the same archive is attached to this release. Branch and tag CI must pass on Linux, macOS and Windows before publication is considered complete.

Limitations: no paid model smoke test was run. Real third-party gateway access, Claude Code subscription inference, coding-plan admission/quota deduction and Tabby desktop/SSH end-to-end behavior remain unverified. Terminal tasks require SSE streaming and function tools. Remote endpoints require HTTPS; HTTP is limited to loopback addresses. Custom headers, query-parameter authentication, non-streaming endpoints and provider-specific custom parameters are unsupported. Custom Chat Completions uses `max_tokens`; Responses uses `max_output_tokens`, stateless storage and encrypted reasoning history options. Partial implementations may reject these fields. Usage remains unknown when the service does not report it. Kimi/Alibaba membership plans are intended for personal interactive coding; choose an appropriate ordinary API for unattended schedules. Tasks run only while Tabby is open.
