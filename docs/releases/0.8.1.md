# 0.8.1 — Reliable CLI startup and inline attachments

Codex background startup and the sidebar now reuse CLI discovery for the same system session space. Supplying explicit system-space metadata no longer cancels the startup connection or produces the misleading “Codex app-server was closed during CLI discovery” / background-service failure alert. Superseded startup attempts cannot report stale failures after a replacement connects.

Concurrent Claude Code connections to the same executable, working directory and session space share one readiness check. Switching targets or closing a connection still cancels discovery, and genuine CLI/authentication errors remain visible and retryable.

The composer accepts clipboard images/files and drag-and-drop directly, with inline names, sizes, removable attachments and image thumbnails. Cached raster previews survive conversation reopening and enforce ownership. SSH upload/download, status, cancellation and verified paths remain available through assistant tools; the old attachment button and transfer popup are removed. Images are not automatically sent to sidebar models or attached to a terminal Agent.

Both READMEs, guide, development/attachment notes, bundled skill/knowledge and synchronized SVG/PNG illustration reflect the final interaction. The existing robot GIF and reduced-motion static fallback are retained.

Validation: Linux / Node 22.23.3 runs 860 tests (854 passed, 6 platform skips), with skill bundle/check, both TypeScript boundaries, production build and whitespace checks. The actual release tarball is checked for complete public artifacts, excluded local files and installation with lifecycle scripts enabled and no node on PATH. Three-platform branch/tag CI and the exact artifact SHA-256 are recorded in the GitHub Release.

These are offline/local fixture checks. Actual Tabby desktop startup, OS clipboard behavior, Windows/macOS desktop operation and real account/model inference have not been newly verified for this patch. The default development shell uses Node 20 and fails two existing Pi fixture setups requiring Node >=22.19; the release checks use the supported Node 22 toolchain.
