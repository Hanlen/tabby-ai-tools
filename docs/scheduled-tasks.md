# 对话中的定时 AI 流程

直接在 AI Tools 对话中描述执行时间、目标和处理规则，例如：

> 每天北京时间 9 点，检查 production SSH 配置对应主机的 /srv/app 服务。先看健康检查和日志；如果异常，判断原因后尝试修复，最多三次；每次操作后重新检查。最后记录结果，无法恢复时说明卡点。

AI 会通过定时任务工具保存任务，返回任务 ID、下一次执行时间和时区。创建任务不会立即执行其中的终端操作。时间、目标主机或完成条件不明确时，需要在对话中补充。任务的执行要求应完整包含这些信息，因为每次运行使用独立会话，不携带创建时整段聊天历史，也不保存临时 tab ID。

支持三种时间规则：带时区偏移的未来时间（单次）、每隔若干分钟（1–525600 分钟）、指定 IANA 时区的每日 HH:mm。每日任务按指定时区计算；夏令时跳过不存在的时间，同一日期的重复时刻只执行一次。固定间隔以创建时间为基准，避免因长任务累计漂移。

## 执行与记录

到点后由插件启动独立 AI 会话，重新发现终端并核对目标。AI 调用与普通对话相同的工具，读取操作结果后决定下一步，可以多次执行、等待、读取和调整方案。每次工具结果都会交回模型；没有把历史命令当作固定脚本重放。

AI 需通过 `scheduled_task_finish` 提交有验证依据的完成结论或需人工处理的原因。普通回合结束但未提交结论时，调度器继续同一次运行，最多 8 个对话回合、30 分钟。API 每回合工具轮数仍使用连接配置；创建时设置的目标 token 预算适用于整次运行，以供应商上报用量为软上限。达到限制不代表完成。

点击输入框旁的 **定时任务**，或输入 `/schedules`：

- 查看当前目录的计划、连接、模型、权限、下一次执行时间。
- 暂停或恢复后续触发，立即运行一次；立即运行不改变原来的时间计划。
- 展开 **执行记录** 查看开始/结束时间、运行 ID、会话 ID、AI 输出、工具操作及返回结果、自动回答、查找依据和最终结论。
- 停止本窗口的本次运行。暂停后续触发不会停止正在执行的一次运行。

**设置 → AI Tools → 定时任务** 显示所有工作目录的任务，支持暂停/恢复、停止和删除。删除前在页面内确认，删除任务及其执行记录；运行中的任务需先停止，等状态结束后再删除。删除与触发共享文件锁，其他窗口正在执行时也不能误删。删除后重启不会再次加载。

完成、失败、中断、需人工处理分别记录。失败、中断、达到限制、需要额外授权或自动查询后仍无法回答时，会暂停该任务的后续触发。检查终端实际状态并处理原因后，可恢复定时或立即运行一次。已经到期的单次任务不能恢复到过去，可立即运行或在对话中创建新计划。

## 为指定任务选择模型

可以在对话中要求：“这个定时任务需要复杂判断，帮我从已配置的连接中选择适合的模型，质量优先，并说明选择理由。”也可以要求成本或速度优先，或者直接指定连接、模型和推理强度。

当前对话中的 AI 通过 `scheduled_task_models` 查看已配置连接和指定连接的实时模型候选，结合任务需求选择。创建任务时可保存 `profileId`、`model`、`reasoningEffort` 和 `selectionReason`；已有任务使用 `scheduled_task_set_model` 调整。选择只保存到这个任务，不修改当前对话、API 连接的模型设置或全局默认值，也不改变任务原有权限、审批和预算。

模型配置更改**从下一次运行生效**，已开始的一次执行继续使用原模型。创建或调整任务时先测试候选，再保存通过测试的选择；候选失败时保存已验证的默认回退，同时保留用户的首选模型。后续触发会重新测试首选，恢复后可以使用首选，失败则仅为本次运行回退。不会在执行中途任意更换模型或重放已执行操作。任务面板显示首选和测试结果，每次执行记录保留本次实际连接、模型、推理强度、测试错误和选择理由，后续更改不覆盖旧记录。

选择范围限定为已配置连接中查询到的模型，或该连接已经配置的模型。实时列表查询不发送模型推理请求，也不返回 API Key、端点、密钥环境变量或会话 ID。列表不可用时会明确显示查询错误，此时仍可沿用该连接已经配置的模型；移除连接不会自动替换为其他供应商。

“可用列表”只能提供候选 ID 及供应商返回的描述，不等于能力排名，也不能证明工具调用兼容性、成本或速度更好。缺少比较依据时，AI 应说明不确定性；模型名称、上下文长度和列表次序不能单独作为“更优”的证据。实际模型效果仍需通过任务运行反馈验证。

## 模型测试与默认回退

可直接指定：“这个任务使用 Codex 的 GPT-6 Sol，推理强度 high；测试失败就使用插件默认模型。”模型 ID `gpt-6-sol` 和 `high` 会分别传给 Codex 的模型与推理强度参数；先用模型列表核对该账号返回的模型 ID 和支持等级，保留用户指定的型号，不自动换成较新型号。参数说明见 [OpenAI 官方 Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)。

执行顺序：

1. 查询模型候选与支持参数；为指定模型发送一次独立的轻量测试请求，要求调用一个无副作用的校验工具。只有文本回复、缺少工具调用、错误 nonce、鉴权错误、限流、不支持参数或超过 60 秒均不算通过。
2. 通过才启用候选。测试失败则读取插件此时的默认连接和模型，再测试默认模型；默认通过就使用它。默认也失败则停止，配置变更保留原任务设置，运行中的预检失败会暂停任务并留档。同一个已失败的默认配置不反复测试。
3. 定时触发时，在真正开始任务操作前再次检查任务指定的模型；测试失败临时回退到当前默认模型，仍保留首选，供下次触发重新测试。预检期间保持执行租约，支持停止和退出取消；取消后不尝试默认模型。

测试会产生实际模型请求和少量用量。API 直接使用相同连接和模型参数检查工具调用能力；Codex 使用独立 app-server、临时空目录和 ephemeral 只读会话，不能操作正常会话或任务终端。测试不证明正式任务一定成功。执行已经发生操作后模型失败，会按原流程停止留档，不自动切换并重放这些操作。

默认模型指 **设置中的插件默认连接及该连接的模型和推理强度**，回退不改动全局设置、当前对话或任务原有权限、审批与预算。运行时可获得的测试用量计入本次 token 预算；失败请求未上报用量时无法精确计数，预算仍是软上限。任务面板及运行记录显示测试通过、回退状态、候选错误和本次实际模型。

这里指定的是负责执行定时流程的插件模型。终端里被控制的另一个 Agent 有独立模型设置；需要切换它时，应在任务要求中指定并读取其界面反馈验证。

## 控制另一个交互式 Agent

可以把 Codex、Claude 等终端 Agent 作为流程的操作对象。例如：“每天 9 点控制已有 Codex，让它在 staging 测试 release 分支；遇到选项和常规问题，按这个目标判断并回答，直到验证完成。”

用户只需要给出任务目标。每次触发后，外层 AI 先读取被控 Agent 的最新输出、当前问题和选择状态，结合目标决定这一步该按什么键、回答什么或继续等待；每次操作后再读一次并重新判断。Agent 改变提示时，后续操作随之改变；流程中不预设按键或回答顺序。`read_tab` 除文字外，还返回光标、当前缓冲区和高亮片段，避免选项状态在纯文本里丢失。`send_keys(tabId,key="Left",shift=true)` 表示 Shift+左方向；另支持方向键、回车、Tab、Shift+Tab、Escape、Ctrl+字母等明确支持的组合。文本回答使用 `send_input(mode=stdin,text=...,submit=true)`。

已经运行的 Agent 可通过 `attach_process(tabId,expectedProcess="codex",purpose=...)` 获取输入控制，不发送 Ctrl+C，也不重启进程。进程名称必须与当前检测结果匹配；每次向接管的 Agent 输入前再次检查进程、会话和所有权。Agent 退出后不继续向 Shell 发送回答。无法检测已有进程的远程终端暂不支持自动接管，可由本次任务启动目标 Agent 后操作。按键遵循 [xterm 键盘协议](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)，终端模式使用 [xterm.js 公开接口](https://xtermjs.org/docs/api/terminal/classes/terminal/)。不同 Agent 的具体快捷键仍以实际界面反馈为准。

终端里被控制 Agent 的常规提问可以按用户任务自动回答；这是终端操作的一部分。外层 AI 后端通过 `requestUserInput` 请求决策时，插件会用本次实际模型开启独立的只读决策会话，结合任务目标、最近记录与选项选择最优答案；信息不足时先查询终端、配置、连接或文档。不机械选择第一个选项。答案与依据写入执行记录后回传原会话，继续本次执行，不弹提问。每次决策最多 3 回合、20 次只读查询、60 秒，每次运行最多自动回答 8 次；用量计入本次预算。需要秘密信息、额外授权、查询后仍无法判断或达到限制时停止留档。决策会话不能操作终端或修改配置，定时执行也不扩大原沙箱范围。执行记录包含每次按键的名称、修饰键、回答文本、读屏结果和最终结论。

交互链路使用模拟 Agent 界面验证了按键、回答、读取反馈和留档。四种 API 协议还用同一个任务目标、三种不同输出分别验证“Shift+Left 后提示 Enter”“Down 后改提示 Tab”“直接询问分支”，以及运行时只等待、不输入。模拟模型逐次读取实际工具反馈生成下一步，没有按请求轮数排列动作；这些测试证明反馈传递和流程衔接，不证明真实模型的判断质量。没有在真实 Codex 交互界面发送按键，实际模型和 Agent 的完整交互仍需实测。

## 生命周期与权限

调度器随插件启动，在配置就绪后自动从本地文件加载计划，无需打开侧栏或设置；收起侧栏后继续工作。**Tabby 必须保持打开**，没有安装操作系统定时器或云端后台服务。关闭期间错过的多个触发会在下次打开时合并执行一次；未执行的单次任务也会执行一次。多窗口共享文件锁与运行租约，同一份配置目录下的定时任务串行运行，不并发抢占终端。

应用退出或运行租约失效后，进行中的运行记为中断并暂停后续触发，不自动重放。停止 AI 不保证已提交的 Shell 命令已经终止，也不会撤销之前的操作，需要根据终端状态核对。

任务保存创建时的工作目录、连接 ID、模型、推理强度、执行权限、审批策略和 token 预算。API 密钥从插件当前连接的直接配置或环境变量读取；插件不访问 Vault，旧 Vault 连接需在设置中改为这两种来源之一。供应商、端点、Thinking 和工具轮数使用该连接当前配置；移除连接会让任务明确失败，不能自动改用其他连接。需要更改已保存的任务要求或时间规则时，先暂停原任务，再在对话中创建新计划。

后台任务统一使用“不询问”策略，包括此前保存为“按需”或“操作时询问”的任务；不会修改普通对话或全局配置。沙箱与任务授权范围保持不变，只读任务仍禁止终端输入等修改操作。后端仍提出额外权限审批时，自动拒绝并留档暂停，不弹审批也不无限等待。终端接管无需人工确认；无关的已检测进程可自动中断，进程检测不可用时读取输出后自主执行。无法确认已中断进程停止、会话变化或被其他任务占用时停止并留档。

## 本地存储

任务与运行记录保存在 Tabby 配置目录同级的 `tabby-agent-schedules/scheduled-tasks.json`。原子替换、写入锁、执行前记录工具意图和运行心跳共同管理任务状态；损坏的文件会报错，不自动覆盖。

最多保存 100 个任务、最近 200 次运行；文件超过 24 MiB 时继续清理最早的已结束记录。每次运行最多记录 499 条事件，每条保留最多 12,000 字符并标注截断。记录对常见密钥格式脱敏，任务要求中发现常见凭据会拒绝保存；请使用凭据引用或环境变量。普通 API / Codex 会话历史仍按原有方式保存，独立于这份执行日志。

任务流程库 `/workflows` 仍是供普通任务参考的本地记忆；这里的定时任务是用户明确授权创建的独立执行计划，两者分别管理。

## 验证范围

单元测试覆盖时区/夏令时、多窗口抢占、重建服务后的启动加载、错过触发合并、单次触发、中断不重放、暂停状态保留、删除持久化和运行中删除保护，以及独立会话、结果分支、多回合继续、无人值守额外审批拒绝、自动查找和回答、停止、取消卡住的决策连接/查询、累计预算及日志失败。四种 API 协议使用本地 HTTP/SSE 模拟响应验证完整的“检查异常 → 执行修复 → 再次验证 → 留档”。真实 Codex 已通过工具注册及会话恢复检查，不调用模型。浏览器使用真实 Angular 模板和模拟任务数据，在 220、320、420、600、1100 像素宽度验证设置页管理、暂停、停止、删除确认及导航；侧栏记录展开另有既有验证。无横向溢出或页面运行错误。这些检查不调用真实供应商、不操作真实 Shell tab；Tabby 桌面与真实供应商的定时执行仍需实测。
