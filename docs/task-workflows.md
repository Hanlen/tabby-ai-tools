# 任务流程与操作偏好

插件会在本地记录已完成终端任务的大致流程，下一次相似任务优先参考此前的操作顺序、命令示例和检查点，减少重复探索。Codex 本机登录和所有 API 连接共用流程库，归档、检索和保存偏好均不额外调用模型。

## 使用

1. 正常发送终端任务。只有本次记录包含已提交的 Shell 命令、命令后的终端读取，且回合和 Goal 均确认完成，才会自动归档。
2. 下次在同一工作目录发送相似请求，插件用本地词项匹配选出一份启用的流程，并附上适用偏好。输入框上方显示引用了哪份流程。匹配支持中文、英文和少量常见 Shell 任务同义词；表达差异较大时可能不命中。
3. 点击对话中的 **任务流程** 或输入 `/workflows`，查看当前目录的归档。**填入任务** 只填入输入框，修改本次参数后再发送。
4. 输入 `/remember 此项目优先使用 pnpm`，将明确的操作习惯保存到当前目录。全局偏好、编辑和删除在 **设置 → AI Agent → 任务流程与偏好** 中管理。

设置中可以编辑流程名称、典型匹配任务和步骤，也可以停用或删除流程。手动编辑的步骤会保留，后续相同任务的归档只更新完成次数。可以关闭自动归档与检索，保留已有流程；输入框旁的“本次不检索记忆”只跳过当前请求的新检索，不移除会话历史中已经出现的参考资料。

## 复用方式

每个请求只附上一份匹配流程和最多八条适用偏好，不传整份任务档案。按工作目录隔离流程，工作目录偏好优先于全局偏好。用户的本次要求始终优先；模型仍需重新读取当前 tab、核对主机、目录、分支、运行状态和参数，并遵守当前操作审批。

流程是供模型参考的资料，没有直接执行、自动重放、固定 tab ID 或绕过审批的通道。任务完成记录不等于插件已经验证每条 Shell 命令的退出码。终端命令的参数和运行环境可能变化，模型需要据此调整步骤。耗时和 token 节省取决于任务和实际命中情况，尚无真实任务基准数据。

## 存储与边界

库文件位于 Tabby 配置文件同级的 `tabby-agent-memory/task-memory.json`，与 API 对话历史独立。文件采用原子替换和写入锁，支持多个 Tabby 窗口同时更新；损坏的文件会提示错误，不会自动覆盖。流程库最多 200 条，偏好最多 100 条。

归档只保存任务描述、步骤、简短结论和次数，不保存终端原始输出、临时 tab ID 或交互式 stdin。常见密钥格式会过滤；含密钥的命令、交互输入、过长或记录不完整的流程不会自动归档。只从录制起点明确的新任务归档，恢复中的任务、连接切换后的尾段、失败和未核对的任务不会拼成完整流程。历史会话仍按原有机制保留。

操作习惯来自成功流程中的实际工具选择，以及用户明确保存的偏好；本版本不会在后台调用模型推断长期偏好，也不会在启动时扫描旧会话生成流程。

## 实现

- `src/task-memory.ts`：归档条件、脱敏、有限词项检索、偏好作用域、流程 CRUD、写入锁与原子持久化。
- `src/task-memory.service.ts`：定位 Tabby 配置目录、共享流程库和全局开关。
- `src/codex-panel.component.ts`：发送前准备参考资料、捕获已返回的 Shell 工具结果、完成后归档；两个后端使用相同入口。
- `src/settings.ts` 与 `src/settings.pug`：流程与偏好管理。

测试使用临时目录、模拟后端和真实 Angular 模板；不读取用户的流程库，不调用真实供应商 API，不操作真实 Shell tab。
