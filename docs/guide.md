## 安装与首次使用

### 准备环境

- 本机安装 [Tabby](https://github.com/Eugeny/tabby)，并能访问所选 AI 服务。操作内网服务器时，本机还需能通过 Tabby 连接目标服务器。
- **ChatGPT 订阅／Codex 登录模式**：本机安装 Codex CLI，在本地终端执行 `codex login`，使用具备 Codex 权限的 ChatGPT 账号登录，再执行 `codex login status` 确认认证状态，无需在插件中填写 API Key。插件默认连接选 **Codex（本机登录）**；可用模型、用量和工作区权限以账号实际权益为准。见 [OpenAI 官方认证说明](https://learn.chatgpt.com/docs/auth)。CLI 需支持 `thread/goal/*`；已测试版本见[验证记录](../VALIDATION.md)。
- **Claude 订阅／Claude Code 本机模式（开发版）**：本机安装官方 Claude Code，运行 `claude auth login`，用 `claude auth status` 核对账号与认证方式。在侧栏或默认连接中选择 **Claude Code（本机登录）**；无需在插件里配置订阅凭据。API Key／云平台可能使用独立计费。完整方案、权限、恢复机制与验证限制见 [Claude Code 接入](claude-code.md)。
- **API 模式**：准备 OpenAI、DeepSeek、GLM、Kimi、百炼 Coding Plan 或 Claude 对应的 Key，无需安装 Codex CLI。订阅登录与 API 连接是两种独立配置方式。

### 安装插件

在 Tabby 打开 **Settings → Plugins**，搜索 **`tabby-ai-tools`**（或 `ai-tools`），安装完成后点击设置页的重启提示（**Restart the app to apply changes**）。安装和升级均在重启后生效；提示不会替你自动重启，可以先处理当前终端工作，再点击重启。这个提示由 Tabby 内置插件管理器提供。插件通过 [npm](https://www.npmjs.com/package/tabby-ai-tools) 分发，新版本可能需要等待搜索索引更新。

插件目前不会自动下载或安装新版。需要更新时，在 **Settings → Plugins → Installed** 点击可用的升级按钮，再点击重启提示加载新版；npm 上发布新版本不会自动更改本机已安装的插件。

从源码安装需要 Node.js 20+：

```bash
git clone https://github.com/Hanlen/tabby-ai-tools.git
cd tabby-ai-tools
npm ci
npm run build
```

在 Tabby 打开 **Settings → Plugins → Open Plugins Directory**，复制实际目录路径，替换下面的占位内容：

```bash
npm run install:tabby -- "<Tabby 插件目录路径>"
```

源码复制安装后，完全退出并重新打开 Tabby，在 **已安装插件** 中确认 AI Tools。本地复制脚本独立于 Tabby 进程运行，不会触发应用内插件管理器的重启提示。构建和安装会自动携带模型使用的 skill，无需单独安装。

### 开始第一个任务

1. 选择本地终端或已连接的目标服务器终端。
2. 启动 Tabby 后 AI Tools 侧栏默认自动打开，无需先进入设置；收起后可点击工具栏机器人图标重新打开。默认使用本机 Codex；Claude Code 可直接在连接列表选择；使用 API 时先按下文添加连接并设为默认，或在侧栏选择连接。
3. 输入“读取当前终端的报错，先分析原因，再提出修复方案”，按 **Ctrl+Enter / Cmd+Enter** 发送。普通 Enter 换行。
4. 在侧栏查看回复、工具结果、提问与审批，在终端核对实际输出。执行中可追加要求，也可点击 **停止**；点击 **释放** 可取回终端输入权。

侧栏顶部的连接（Provider）与模型（Model）并排显示；长名称可悬停查看。状态详情等面板只滚动内容区，标题栏与关闭按钮始终保留在顶部。

## 基础配置

打开 **Settings → AI Tools**。配置自动保存；修改连接参数后，在侧栏点击连接图标应用。默认连接和当前正在编辑的连接分别选择，编辑连接不会自动把它设为默认。

| 配置 | 设置方法与作用 |
| --- | --- |
| 默认连接 | 选择本机 Codex、Claude Code 或已添加的 API 连接；也可在侧栏顶部切换，保留当前对话。 |
| Codex CLI 可执行文件 | 默认 `codex`，也可留空自动发现；指定时只填路径或命令名，不附参数。找不到时见[启动排查](#cli-自动发现与启动排查)。 |
| Claude Code CLI／模型 | 在连接列表选择 Claude Code，填写 CLI 路径（默认 `claude`）和模型别名／ID（默认 `sonnet`）。订阅登录通过官方 CLI 完成；推理强度可选。 |
| 固定工作目录 | 留空时读取当前本地终端目录，读取不到则使用用户主目录；可指定本机目录。远程终端目录不会自动成为本机工作目录。 |
| 模型与推理强度 | Codex 模型留空时沿用 CLI 默认；侧栏点击模型摘要或使用 `/model` 选择，下一回合生效。API 与 Claude Code 同样先选模型，再选推理强度；两项一起应用。 |
| 沙箱／文件访问 | 默认为工作目录可写，可选只读或完全访问。Codex 本地工具使用其沙箱；通过 Tabby 发送的命令使用目标终端账户的实际权限。只读模式禁止终端输入及修改操作。 |
| 审批策略 | 默认为按需询问，也可选不可信命令询问或不询问；侧栏修改在下一回合生效。定时任务使用无人值守策略，见[定时说明](scheduled-tasks.md#生命周期与权限)。 |
| 每个目标的 token 上限 | `0` 表示不设置上限；达到预算不代表完成。API 用量依赖服务商上报，预算为软上限。 |
| 启动时打开侧栏 | 默认开启，已有明确关闭设置会保留；取消后下次启动不自动打开。 |
| 界面语言 | 默认跟随 Tabby，也可独立选择。 |
| 任务流程与偏好 | 管理显式录制、流程别名和全局／目录偏好。 |
| 定时任务 | 查看所有目录的计划，暂停、恢复、停止或删除。 |

API 模式不提供 Codex 的操作系统沙箱，操作命令使用终端账户本身的权限。选择连接、模型或权限不会为服务器账户增加权限。

## 内网服务器与 sudo 临时认证

本机负责连接模型服务，Tabby 的 SSH 会话负责连接服务器。服务器无需访问外网，也无需安装 Agent。模型分析所需的终端输出由本机发送给所选服务；这并非离线模型模式。

1. 在 Tabby 中创建或打开目标服务器的 SSH 连接，完成登录。
2. 从该终端打开侧栏，在任务中明确目标连接、主机、目录和操作范围。
3. AI 通过该终端读取状态、发送命令并核对结果。Codex 自身的本地 Shell／文件工具仍在本机执行，远程操作需使用相应终端工具。

需要 sudo 时，先取回目标终端输入权，在**目标服务器的同一终端**手动执行：

```bash
sudo -v
```

也可以执行 `sudo ls`，自行输入密码，等待命令返回后再让 AI 继续。无需把密码写进对话、任务要求或脚本。后续 sudo 是否免于重复输入、缓存有效期和适用范围取决于服务器配置；更换终端或认证过期后可能需要重新认证。需要时可在该终端执行 `sudo -k` 使认证缓存失效。

定时任务不能等待你输入密码。临时 sudo 认证不保证在未来触发时仍有效；运行中需要密码或额外授权时，任务会停止留档。

## 任务编排与多服务器协作

任务编排通过对话目标和终端反馈推进，支持跨标签、多步骤、条件判断、等待和再次验证。它不要求在每台服务器上分别部署 Agent，也不需要先编写固定脚本或配置 DAG。

发起任务时写明：**目标连接／主机、目录、操作顺序、条件分支、授权范围、重试次数和完成标准**。例如：

> 使用 staging-db 和 staging-app 两个 SSH 配置。先确认数据库可用，再检查应用与数据库的连接；如果数据库正常而应用连接失败，检查应用配置并说明原因。得到我的确认后修改配置，重启应用并验证健康检查；最多尝试两次，仍失败就说明卡点。

AI 会发现并核对各连接与终端，将每一步的实际输出作为下一步依据。终端接管无需人工确认；检测到无关前台任务时由 AI 判断后自动中断，SSH 等无法检测进程的终端先读取输出再自主执行。新连接的认证仍可能需要人工处理。多台服务器协作不等于同时执行；定时任务在同一配置目录下串行调度。

也可以要求 AI 操作终端中的 Codex、Claude 等交互式 Agent：根据其最新输出回答问题、发送按键并读取反馈。已有进程需可检测并通过接管检查；状态未知的远程现有进程不能自动接管。详见[交互式 Agent](scheduled-tasks.md#控制另一个交互式-agent)。

以 `/remember 任务描述` 开始的任务在成功核对后保存流程，并提示设置别名；下次发送 `/task1` 即执行。普通任务不自动固化。查看[流程复用与偏好](task-workflows.md)。需要定期执行同一目标时，在对话中明确创建[定时任务](scheduled-tasks.md)，保存完整的目标与处理规则。

## 界面语言

在 **Settings → AI Tools → 界面语言** 选择跟随 Tabby，或独立指定语言。支持英语、简体中文、繁体中文、西班牙语、法语、德语、葡萄牙语、俄语、日语、韩语、阿拉伯语和印地语；区域语言代码会匹配对应语言，不支持的语言和缺少的翻译回退到英语。阿拉伯语界面采用从右向左排版。

语言文件随插件分发，使用期间无需联网翻译。仅翻译插件的界面和提示；用户消息、模型回复、终端输出、连接名称和保存的任务内容保留原文。部分语言由机器翻译提供初稿，欢迎提交校对。默认 README 为[英文](../README.md)，另提供[简体中文](../README.zh-CN.md)。

## API 密钥与切换模型

1. 打开 **Settings → AI Tools → 添加 API 连接**，选择供应商并为连接命名。
2. 确认 Base URL，填写基础地址，不附加 `/responses`、`/messages` 或 `/chat/completions`。可使用对应协议的代理地址；GLM 按平台和套餐选择端点。
3. 直接填写 API Key，或指定 Tabby 进程可读取的密钥环境变量。
4. 获取模型列表并选择模型，或手动输入完整模型 ID，然后点击 **测试连接**。
5. 将连接设为默认，或在侧栏选择它；修改参数后点击侧栏连接图标应用。

| 供应商 | 协议 | 默认密钥环境变量 |
| --- | --- | --- |
| OpenAI API | Responses | `OPENAI_API_KEY` |
| DeepSeek | Chat Completions | `DEEPSEEK_API_KEY` |
| GLM | Chat Completions | `ZAI_API_KEY` |
| Kimi API | Chat Completions | `MOONSHOT_API_KEY` |
| Kimi Coding Plan | Chat Completions | `KIMI_API_KEY` |
| 阿里云百炼 Coding Plan | Chat Completions | `BAILIAN_CODING_PLAN_API_KEY` |
| Claude | Messages | `ANTHROPIC_API_KEY` |
| 自定义（OpenAI 兼容） | Chat Completions（默认）或 Responses | `CUSTOM_API_KEY` |

Kimi API、Kimi Coding Plan 和阿里云百炼 Coding Plan 提供 **中国内地／国际** 区域选择，切换会自动填入对应端点；密钥须与购买平台和套餐匹配。手动地址不会被自动覆盖。完整端点表、默认模型、思考参数与使用范围见 [Coding Plan 配置](coding-plans.md)。套餐用于个人交互式编程；无人值守定时任务应使用普通按量 API。

修改环境变量后需要完全退出并重启 Tabby。API 模式当前不自动压缩上下文，长任务可用 `/new` 新建会话；用量显示请求和本地累计 tokens，不显示 Codex 订阅额度。协议和存储设计见[多模型 Agent 说明](multi-provider-agent.md)。

在 **Settings → AI Tools → 添加 API 连接** 配置供应商、Base URL 和模型 ID。密钥来源默认选择“直接输入”，填写 API Key 即可，该方式将密钥保存在本地 Tabby 插件配置中。也可选择环境变量；自定义接口还支持“无需密钥”。插件不访问 Vault，旧 Vault 连接需重新选择密钥来源。

设置页通过连接列表切换编辑对象，一次只显示一个连接的配置。列表显示供应商、模型和默认标记，各供应商使用不同色标；编辑区标题始终保留当前连接身份，表单独立滚动。窄窗口下列表改为横向滚动。新增连接自动进入编辑，删除当前连接后切换到相邻连接；Codex 本机引擎也从列表单独选择。切换编辑对象不会改变默认连接，默认连接通过顶部选择器或编辑区的“设为默认”修改。思考模式、推理强度、上下文窗口和工具轮数上限在 **高级参数** 中展开配置。

点击当前连接编辑区下方的 **测试连接** 会发送一条简短请求，实际验证密钥、模型和流式响应，并产生少量 API 用量。进度与结果显示在按钮下方，测试中可以取消，60 秒超时；HTTP 错误、错误模型或不支持 SSE 的代理会显示相应提示。

配置端点和密钥后，聚焦模型 ID 输入框会自动获取列表；也可点击 **获取模型** 刷新，从建议中选择或手动填写 ID。侧栏点击模型摘要或输入 `/model` 同样会自动读取当前连接的模型列表。列表不支持或获取失败时，可在选择器中手动输入模型 ID；仍会进入推理强度选择，模型与等级一起应用。所有连接统一先选模型，再选 reasoning，支持服务商默认值；API 和 Claude Code 也可手动填写模型接受的原始等级。优先显示服务端上报的能力；没有元数据时，对已知模型提供保守的官方等级选项，未知模型提供默认值和手动输入。顶部模型摘要同时显示当前 reasoning；支持的 Thinking 开关单独保留，窄侧栏会自动换行。

DeepSeek 的 Thinking 开关在顶部保留，Low / High / Max 等级统一在模型浮窗中选择。关闭 Thinking 后不发送可能将其重新打开的推理强度参数；在浮窗主动选择非空等级会重新启用 Thinking，使等级生效。点击模型摘要或 `/model` 选择模型与推理强度，侧栏中的修改会自动应用。设置页修改供应商、端点或模型后仍需点击连接图标应用配置。思考阶段显示接收进度，正文增量到达后立即刷新；实际片段到达速度取决于服务商和代理。

API 连接的“每回合工具轮数上限”设为 **0** 时不按固定次数中止任务，新连接默认使用 0；历史默认值 20 自动迁移为不限，无需逐个修改。其他已有自定义数值保留；今后主动设置的 20 也会保留。设为 1–100 时，仅工具调用轮次计数，最后额外保留收尾请求读取结果、更新一次目标状态并给出回复，收尾阶段不再操作终端；目标未完成仍显示未完成。停止和目标 token 预算在两种模式下都生效。读取受控终端默认等待 1 秒，也支持等待最多 30 秒后读取，减少等待命令输出时的空轮询。

API 与 Claude Code 的 Goal 仍为 active 时，普通文本回复或阶段总结不会结束执行；运行器在同一回合内自动继续，不询问是否 Continue goal。模型核对原始要求并验证结果后须调用 `agent_goal_update(status=complete, evidence=...)`。确实缺少用户信息、凭据、额外授权或外部依赖时可标记 blocked 并说明原因；仅用户明确要求暂停时使用 paused。停止、预算、主动设置的工具轮数上限和重复无进展检测仍有效；自动续行不绕过操作审批，不重试失败的模型请求，也不会重放历史命令。定时任务仍遵守其独立的整次运行限制。

API 工具循环检测始终启用，无需等到轮数上限。近期同一段操作和结果连续出现三次（包括 A→B→C→A→B→C→A→B→C）时，会拦住后续工具，让模型总结卡点，并将目标标记为受阻；同一批剩余操作也不会执行。比较终端新追加的输出，忽略参数顺序、等待时长及操作说明的变化；运行中或状态未知的进程仅因画面不变不会触发，单纯“输入已发送”的回执也不能证明没有进展。检测记录随会话保存，直接继续或重启后重放同一循环的下一条命令会在发送前拦截；新目标清空记录。检测依据实际工具调用和结果，不能保证识别命令写法不同但含义相同的方案。

任务结束后，在侧栏切换 API 连接，或在 DeepSeek 等 API 和 Codex 本机登录之间切换，都会带上当前对话、转发的终端输出、工具结果和任务目标。历史会转换成目标接口可用的文本，内部推理内容不会跨模型传递，历史工具不会重新执行。切回之前的连接时继续当前对话；旧快照仍可用 `/resume` 恢复，输入 `/new` 则开始空白对话。转入 Codex 时持久化导入的历史以供显示和重启恢复，并为模型设置历史文本；导入的进行中目标等到下一次主动发送消息后才激活，切换本身不触发推理。

### 自定义 OpenAI 兼容接口

1. 添加 API 连接，供应商选择 **自定义（OpenAI 兼容）**，为不同网关或本地服务分别命名。
2. 默认选 **Chat Completions**（请求 `/chat/completions`）；服务明确支持 Responses 时再切换为 **Responses**（请求 `/responses`）。不会自动尝试另一协议，避免重复请求和计费。
3. 填写服务提供的基础地址，例如 `https://gateway.example/v1` 或 `http://localhost:1234/v1`。保留必需的 `/v1` 或其他前缀，不附加具体请求路径。自定义连接没有默认云端地址；空地址会报错。远程地址要求 HTTPS，HTTP 仅允许 `localhost`、`127.0.0.1`、`[::1]`，不支持普通内网 IP 的 HTTP。
4. 选择直接输入 API Key 或环境变量（默认名称 `CUSTOM_API_KEY`），使用标准 Bearer 认证；不需要认证的本地服务可选 **无需密钥**。此模式不读取原来保存的 Key，也不发送 Authorization 请求头。切回内置供应商时恢复密钥认证。
5. 获取模型列表，或手动填写服务要求的完整模型 ID（可包含命名空间）。聚焦输入框只获取列表，不调用推理；`/models` 不可用不影响手动配置。点击 **测试连接** 才会发送简短推理并产生相应用量，该测试不证明工具能力可用。
6. 在侧栏选择连接或设为默认；设置修改后点击连接图标应用。可以保存多个独立自定义连接。切换协议、端点或模型时保留通用对话上下文和目标，不会重放历史工具调用；相同协议可恢复原生历史。

终端 Agent 需要服务和模型都支持 SSE 流式响应及 function tools。自定义连接复用现有文本、工具、审批、停止、目标和历史功能，不发送厂商专用 `thinking`、`enable_thinking` 或缓存参数。推理强度默认留空；填写后按协议发送 `reasoning_effort`（Chat Completions）或 `reasoning.effort`（Responses），具体值由服务决定。Chat Completions 使用 `max_tokens`，Responses 使用 `max_output_tokens`、`store: false` 和加密推理历史选项；仅兼容部分协议的网关可能拒绝这些字段。服务上报的 usage 才能计入真实 token 用量，自定义 Chat Completions 不强制发送 `stream_options`；未上报时保持未知。暂不支持自定义请求头、查询参数认证、厂商专用字段或非流式接口。

离线 HTTP/SSE 夹具已覆盖两种协议及工具往返；未知第三方网关和真实 Tabby 桌面显示需按实际服务验证，不能因“OpenAI 兼容”而视为所有厂商能力均可用。

## 重复任务与操作习惯

用 `/remember 任务描述` 明确开始录制，插件执行任务并记录已核对的终端步骤；完成后提示是否设置别名，例如 `task1`。之后直接发送 `/task1` 执行流程。普通任务不再自动归档，也不再按相似描述自动匹配；输入框中的“不检索记忆”复选框已移除。点击 **任务流程** 或输入 `/workflows` 查看当前目录的流程，设置中可以给已有流程添加别名。

含 sudo 的流程会提前提示在每个实际执行终端运行 `sudo -v` 或 `sudo ls`，完成认证后继续。其他终端的认证不保证共享。执行时用 `sudo -n -v` 预检，每 30 秒非交互刷新；认证失效时停止该命令并要求重新认证。详情和清理边界见[任务流程说明](task-workflows.md)。各步骤还保存服务器 IP、持久连接／服务器 ID、操作路径、前置依赖和验收证据。跨服务器也逐步执行：读取对应终端的新结果，并通过步骤确认工具验收后，才放行下一步；目标或路径不符时停止。操作偏好继续在设置页管理，`/remember` 专用于开始任务录制。

## 定时 AI 流程

在对话中提出“每天北京时间 9 点检查服务，异常时分析日志并修复，最多三次，最后验证恢复”等要求。AI 会保存独立定时任务，触发后根据每次输出继续判断和操作，留下逐次执行记录。支持单次、固定分钟间隔和指定时区的每日任务。

点击 **定时任务** 或输入 `/schedules` 查看计划、暂停/恢复、立即运行、停止本次运行、展开执行记录。设置 → AI Tools → 定时任务显示所有目录的计划，支持暂停、恢复、停止和删除任务及记录。定时会话不等待用户，遇到问题先查找并自主选择最优答案，保留原沙箱范围。任务在重启后自动加载，仅在 Tabby 打开时执行；关闭期间错过的触发合并一次，异常中断不自动重放。详情见[定时任务说明](scheduled-tasks.md)。

也可让外层 AI 控制另一个终端 Agent：读取提问，发送 Shift+方向键、回车等按键，按原始目标回答，再检查反馈。支持接管已检测到的现有进程；具体边界见[交互式 Agent 说明](scheduled-tasks.md#控制另一个交互式-agent)。

可在对话中要求为某个定时任务选择适合复杂判断、速度或成本偏好的模型。AI 查询已配置连接的模型候选后，将选择和理由只保存到该任务；已有任务的更改从下次运行生效。参见[任务独立选模](scheduled-tasks.md#为指定任务选择模型)。

指定任务模型（例如 Codex `gpt-6-sol`、推理强度 `high`）会先发送轻量测试；失败则测试并使用插件默认模型，默认也失败就停止留档。测试会产生少量用量，详见[测试与回退](scheduled-tasks.md#模型测试与默认回退)。

## 后台连接与生命周期

AI Tools 默认在启动 Tabby 时自动展开侧栏，使用默认连接，无需先进入设置启用。未保存过此选项的已有配置也会默认打开；已明确关闭的配置保持关闭。如需关闭，在 **Settings → AI Tools** 取消勾选 **启动 Tabby 时自动打开 AI Tools**，下次启动生效。工作目录沿用工具栏打开侧栏时的规则：优先使用固定目录，否则尝试读取当前本地终端目录，无法读取时使用用户主目录。手动收起后，本次运行不会再次自动展开。

插件加载并读取配置后会立即启动常驻的 `codex app-server --listen stdio://`，每个 Tabby 窗口共用一个进程。打开、收起或切换侧栏均复用该服务，通过 JSONL 通知逐段显示流式应答。进程异常退出后自动重连，重试间隔从 1 秒逐步增加到最多 30 秒；服务启动失败会提示检查 CLI 路径。修改并保存 CLI 路径后自动更换进程，其他设置保存不会重启服务。窗口退出或插件销毁时关闭进程并清理重连定时器。

## 工作目录与线程

- 默认读取当前本地终端的工作目录；设置页可指定固定目录。每个目录保存一个 Codex 线程 ID；收起侧栏后面板仍保留，重启 Tabby 后调用 `thread/resume` 恢复上下文。首次升级到支持全标签工具的版本时会为该目录创建新线程，旧线程仍保存在 Codex 本地历史中。

- 再次点击工具栏图标会打开同一侧栏；切换目录时复用对应目录的面板和线程。Codex 侧栏独立位于普通标签栏左侧，右边缘可以拖动改变宽度，宽度会记住。灰色按钮表示连接或会话恢复中，绿色表示会话已就绪，红色表示未连接，点击可重连。输入 `new` 或 `/new` 会创建新线程，旧会话和目标保留，可用 `/resume` 恢复。

- 输入 `/resume` 仅查看当前工作目录下由 Tabby AI Tools 创建的会话，再次输入可关闭列表。列表显示标题或首条消息、更新时间和当前会话标记；点击某项即可恢复，也可在空输入框中用上下方向键选择、Enter 恢复、Esc 关闭，支持刷新和分页加载。正在执行任务时可在列表中点击“停止当前任务”，等待停止后再恢复；等待回答或审批时请先处理。

## 标签访问与终端控制

- Codex 可用 `tabby_tabs` 工具列出当前窗口的全部标签及分屏终端、读取终端屏幕和滚屏、切换标签，并向任意仍在运行的终端发送输入。普通标签可读取其文本和控件，按控件 ID 点击或填写。标签和控件 ID 仅在当前 Tabby 窗口中有效，操作前应重新读取。

- 侧栏第二行以“控 N”显示 Codex 当前控制的终端数量，无控制时仅显示短占位。AI 提交命令后，该 Tab 的用户输入会暂时锁定；可靠的 Shell 完成信号确认命令结束时自动释放；仅没有子进程不足以证明结束，无 Shell 集成时需读取返回的提示符与结果后显式释放，Codex 也可调用 `release_tab` 释放。用户可随时点摘要旁的 **释放** 释放全部受控终端，或在 **详情 → 终端控制** 中逐个点 **临时释放** 取回输入权；当前回合结束、连接断开或标签关闭时也会释放。锁定期间终端仍可查看输出。

- 向已有进程的终端发新命令前，Codex 应先读取 Tab 并判断现有任务是否仍需要。需要时插件阻止覆盖；不需要时侧栏显示进程和新命令用途，由用户决定是否先发送 Ctrl+C。远程会话等无法检测进程状态的终端，会要求用户确认空闲或同意中断；中断后还需确认已回到命令提示符，才会发送新命令。拒绝后不会发送新命令。`getChildProcesses` 只表示本地会话有子进程，不能严格证明它就是前台进程；遇到不确定状态请核对终端内容。

## 输入与命令

- 输入框下方，文件访问与操作审批控件位于发送按钮左侧，与发送、停止按钮保持同一行；选择会保存到设置，并在下一个回合生效。

- 输入框中按 ↑ 回看当前会话已发送的消息，按 ↓ 返回较新的消息，翻到最新之后会恢复未发送的草稿。多行输入仅在首行按 ↑、末行按 ↓ 时翻历史；恢复旧会话后也可回看其中的输入。

- 在输入框键入 `/` 可查看面板支持的命令，用上下方向键选择、Enter 执行、Esc 收起列表。普通消息的 Enter 用于换行，`Ctrl+Enter` 或 `Cmd+Enter` 发送。`/model` 打开当前连接的模型列表，选模型后再选推理强度（Thinking level）；Codex 以模型上报的能力为准，API 与 Claude Code 还支持服务商默认与手动输入；两项一起保存并在下一回合生效。“当前 Codex 默认”会保存列表上报的具体模型 ID，已有会话也会切换到该模型。也可输入 `/model 模型ID` 进入该模型的推理强度选择。

## 模型、状态与用量

- 顶部常驻显示当前模型和 reasoning 等级，包括会话实际使用的 Codex 默认配置；点击可切换模型与推理强度，下一回合生效。执行中保留当前回合的模型信息。顶部还显示 Codex、短目录名（悬停可查看完整路径）、连接图标、**详情**、关闭按钮，以及任务状态、上下文占比、终端控制数量和“转发开/关”。长目录名、长任务状态会截断，状态悬停可查看全文。点击 **详情** 或状态摘要可展开或收起详情。

- 发送被拒绝或回合执行失败时，对话区和输入框上方会显示具体原因。用量/频率超限提示等待恢复，并在已收到额度信息时显示重置时间；上下文和预算超限给出相应处理提示。同步发送失败会恢复输入内容；自动重试期间保留执行状态，收到正常回答后清除输入框上方的错误提示。

- **详情**（也可输入 `/status` 打开）完整显示路径、会话 ID、任务状态、查询时 Codex 上报的模型与运行状态、上下文 token 和会话累计、额度、普通用量是否可用、目标、权限、控制终端列表及自动转发说明，并保留 **刷新** 查询。各项独立读取，部分读取失败时仍显示其他信息。详情高度受限且可滚动，窄侧栏内完整信息自动换行；详情与 `/resume` 历史列表互斥。历史、输出等异常通知仍直接显示。还支持 `/new` 和 `/help`。

- 上下文摘要收到 Codex 的 token 用量通知后显示百分比；未上报时显示“上下文 —”。**详情** 显示最近一次模型请求的用量、上下文窗口大小和会话累计 token；切换会话时会清空旧会话数字，等待新通知。

## 任务目标与交互

- 每条新任务会设置一个持久 Goal。Codex 的消息、命令输出和审批请求会实时显示。任务运行中发送新文本会追加到当前回合。

- Codex 的交互提问会在侧栏显示为可点击的选项按钮，支持“其他”自由输入；提交后继续任务。若问题附在流式回复中，插件会暂停当前回合，等用户回答后继续。

## 消息与历史显示

- 对话消息可以选中文字并使用系统快捷键复制；每条消息也有“复制”按钮。

- 对话默认自动滚动到最新消息，流式回复和工具输出会持续跟随。上翻查看历史时暂停自动滚动，显示“回到最新消息”按钮；点击按钮或手动滚回底部后恢复跟随。恢复其他会话时直接定位到最新消息。

- 恢复会话时先读取元数据，再按 Codex 的历史模式加载旧消息。若本机 app-server 暂不支持历史分页，侧栏会提示旧消息不可用；已恢复的会话仍可继续对话。

## 终端输出与远程环境

- 从终端点击工具栏图标会绑定该终端作为自动转发源；按游标只把新片段送给 Codex。同目录有多个终端时，恢复后的 AI 面板不会猜测自动转发源，需要从目标终端再次点击工具栏图标。AI 面板可随时在 **详情 → 自动转发** 中点击 **停止自动转发**；之后也可从终端重新绑定。独立的 `tabby_tabs` 工具会监控当前窗口的所有终端标签，以便 Codex 按需读取任意标签；停止自动转发不关闭工具读取能力。

- 新任务启动时最多附带 6,000 字，运行中每批最多 2,000 字、每回合最多 16,000 字，超出部分留给后续回合。缓存只保留已绑定终端最近 32,768 字；缓存溢出时会明确标记截断。`new` 会丢弃旧会话的未发送终端输出。

- Tabby 提供的是终端会话的 PTY 输出流。插件目前无法从普通输出流准确判断一条命令的起止、退出码或输出所属进程；全屏程序、持续日志和交互式命令可能产生大量无关片段。终端输出会作为不可信数据传给 Codex，请在显示敏感信息前停止读取。

- Codex CLI 的本地 Shell／文件工具仍在本机执行；通过 `tabby_tabs` 发送到 SSH 或容器终端的命令则在对应终端中执行。读取远程输出不会自动切换本地工具的工作目录或执行环境。单个协作任务可以使用多个终端；无关的服务器任务建议使用独立会话，并明确目标主机，避免混淆。

## 完成状态与默认权限

- 只有回合状态为 `completed`，且 Goal 状态为 `complete`，界面才显示“任务已完成”。Goal 仍为 `active` 时，Codex 可以自动继续；必要时点击“继续当前目标”。失败、被中断、达到预算或等待用户处理均显示未完成。

- 默认沙箱是“工作目录可写”、审批为“按需询问”。审批请求会显示在 AI 标签页；可在设置中调整。`Ctrl+Enter` 发送消息。

Goal 通过证据检查和持续执行降低过早结束的概率，但无法数学保证模型做出的每项工作正确。请根据最终文件、测试和工具输出核对关键结果。

## CLI 自动发现与启动排查

`codexAgent.executable` 留空或保持默认 `codex` 时，先从 **Tabby 自身进程的 PATH** 查找并验证文件，随后检查 `CODEX_INSTALL_DIR`。Windows 再检查官方独立安装入口 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`，再检查 `CODEX_HOME` 下的 standalone 内部入口，随后扫描桌面安装 `%LOCALAPPDATA%\OpenAI\Codex\bin\<目录>\codex.exe`。桌面安装目录名可以是哈希，按有效 **codex.exe 的修改时间降序** 选择，时间相同按完整路径排序；不从目录名推断版本。每次启动后台进程都会重新查找，以适配升级和旧目录清理；已有连接复用当前进程。

Linux/macOS 在默认命令模式下会异步启动 `$SHELL -ilc` 补全环境，即使桌面 PATH 已经包含 Codex，也会读取用户 Shell 中的 Codex 配置。未设置 SHELL 时，Linux 使用 `/bin/bash`，macOS 使用 `/bin/zsh`；支持 bash/zsh/sh/dash/ksh/fish。探测限时 3 秒，通过独立管道读取最多 64 KiB，忽略 Shell 启动输出。仅导入 PATH、CODEX_HOME / CODEX_SQLITE_HOME / CODEX_INSTALL_DIR、NVM_DIR、HOMEBREW_PREFIX、NPM_CONFIG_PREFIX / npm_config_prefix、代理、证书及 OPENAI_API_KEY / CODEX_API_KEY / CODEX_ACCESS_TOKEN；其中非 PATH 变量以父进程已有值（包括空值）为准，不导入 Shell 的 NODE_OPTIONS 等运行时钩子，也不把环境变量内容写入诊断。

默认 Codex 仍未找到时，按下表补充安装来源。POSIX 先恢复用户 Shell 环境，再检查 standalone、配置的 prefix、NVM 和常见系统目录；Windows 保留上文的独立安装／桌面安装优先级，再查 npm 等目录。尚未找到时才查询包管理器 prefix，随后检查 macOS 桌面包，最后才扫描 IDE 扩展。已通过 PATH 或设置选定的 Codex 不会被另一安装替换。

| 来源 | macOS / Linux | Windows |
| --- | --- | --- |
| PATH | `codex` | `codex.exe`、`codex.cmd` 等 PATHEXT 支持的启动器 |
| 官方 standalone | `~/.local/bin/codex` | `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe` |
| 自定义 standalone | `$CODEX_INSTALL_DIR/codex` | `%CODEX_INSTALL_DIR%\codex.exe` |
| standalone 内部入口 | `${CODEX_HOME:-~/.codex}/packages/standalone/current/bin/codex`，兼容 `current/codex` | `%CODEX_HOME%\packages\standalone\current\bin\codex.exe`，兼容 `current\codex.exe`；未配置时使用 `%USERPROFILE%\.codex` |
| Homebrew | `$(brew --prefix)/bin/codex`，也检查 `HOMEBREW_PREFIX/bin` 和常见 Homebrew/Linuxbrew 目录 | — |
| npm | `$(npm prefix -g)/bin/codex`，也检查配置的 npm prefix、`~/.npm-global/bin` | `$(npm prefix -g)\codex.cmd`，也检查配置的 npm prefix 和 `%APPDATA%\npm` |
| NVM | `$NVM_DIR` 和 `~/.nvm` 的 `current/bin`、`versions/node/v*/bin` | — |
| macOS 新桌面包 | `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`，同样支持 `~/Applications` 和 `Codex.app` | — |
| macOS 兼容入口 | `/Applications/ChatGPT.app/Contents/Resources/codex`、`/Applications/Codex.app/Contents/Resources/codex`，同样支持 `~/Applications` | — |
| Windows 桌面兼容目录 | — | `%LOCALAPPDATA%\OpenAI\Codex\bin\<目录>\codex.exe` |
| IDE 扩展最后兜底 | `~/.vscode/extensions/openai.chatgpt-*/bin/<platform>/codex` | `%USERPROFILE%\.vscode\extensions\openai.chatgpt-*\bin\<platform>\codex.exe` |

包管理器只执行已安装命令的 `brew --prefix` / `npm prefix -g`，不安装或更新软件。两项查询并发，各限时 2 秒，stdout 最多 16 KiB，只接受单行绝对路径；失败、无效输出或超时后继续查找，关闭／切换配置会取消并回收查询进程树。npm 查询也可使用从 NVM 恢复的 Node。诊断不包含包管理器输出或环境变量值。standalone 路径与布局依据官方 [POSIX 安装脚本](https://github.com/openai/codex/blob/main/scripts/install/install.sh) 和 [Windows 安装脚本](https://github.com/openai/codex/blob/main/scripts/install/install.ps1)；npm prefix 与 bin 位置见 [npm prefix](https://docs.npmjs.com/cli/v12/commands/npm-prefix/) 和 [npm folders](https://docs.npmjs.com/cli/v12/configuring-npm/folders/)。

NVM 优先 current，其余按 Node 版本降序。IDE 同时支持 `.vscode-insiders`、`.vscode-server` 和 `.vscode-server-insiders` 的 extensions 目录，只检查 `openai.chatgpt-*`，按扩展版本降序选择当前 OS／x64 或 arm64 架构的有效文件，跳过缺失或不兼容的候选；不运行扩展自带的任意安装脚本。IDE 和桌面包内部路径属于兼容兜底，布局变化或自定义位置仍可填写实际完整路径。POSIX 候选必须有执行权限，目录和断开的软链接不会被选中。

查找结果与启动环境一起传递：Linux/macOS 把启动器所在目录放到子进程 PATH 首位。对于 `#!/usr/bin/env node`（含 `env -S node`）启动器，若 Node 不在同目录或 PATH，则从用户 Shell 及 NVM 等补充目录恢复 Node；这也适用于有效的显式路径和自定义命令名。找不到 Node 时报告运行环境错误，保留选定的 Codex。父进程环境不变，关闭或切换配置会取消尚未结束的探测。

服务关闭和重连会等待旧进程回收。Linux/macOS 为服务创建独立进程组，先发送 SIGTERM，等待最多 1 秒，再向仍存活的进程组发送 SIGKILL，并等待最多 2 秒确认服务管道关闭。Windows 使用由 SystemRoot / WINDIR 定位的绝对路径 `System32\taskkill.exe /t /f`，不依赖 PATH；执行和退出确认均有 2 秒上限。回收失败会给出诊断并阻止启动另一个服务，需要处理该错误并重启 Tabby 后重试。

显式配置的绝对路径、相对路径或 `~/` 路径优先（可带一对外层引号），会验证真实文件存在；无效立即报错，**不会自动降级到另一安装**。自定义命令名（如 `my-codex`、`codex.cmd`）仅按 PATH / Windows PATHEXT 查找，保留命令名配置兼容性；未找到也不会改用桌面安装。Windows 支持原生 exe/com 和 cmd/bat 启动器，含空格、中文路径可用。原生程序使用绝对路径、参数数组和 `shell:false`；cmd/bat 由 cross-spawn 负责 cmd.exe 转义，stdin/stdout JSONL 及 stderr 均保留为管道。只填写文件路径或命令名，不附加参数。

子进程环境会移除所有大小写形式的 `CODEX_INTERNAL_ORIGINATOR_OVERRIDE`，初始化始终使用插件自己的 `clientInfo.name = tabby_codex_agent`，父进程环境不变。定位失败会给出 PATH 检查情况、Windows 安装扫描路径或 LOCALAPPDATA 缺失、Linux/macOS 的 Shell 探测结果及补充安装目录、候选拒绝原因，以及 **Settings → AI Tools → Codex CLI 可执行文件（`codexAgent.executable`）** 设置入口。

出现 `Codex app-server exited (1)` 时，侧栏会同时显示实际启动路径和 CLI 的错误输出。可在终端运行 `codex app-server --listen stdio://` 查看相同安装的启动错误；命令启动后等待输入是正常现象，按 Ctrl+C 退出。路径、Codex 配置和安装问题应以错误输出为准。

本地安装后请在 **已安装插件** 中查看；**可用插件** 列表来自 npm 搜索，未发布到 npm 的本地包不会出现在该列表。
